The problem

Working across several AI assistants meant repeatedly switching windows to check whether a response had finished. GitHub Actions added another place to watch. The goal was small and practical: make finished work noticeable without turning a notification tool into another dashboard to manage.

The design decisions

  • One companion, two views. A draggable floating icon stays visible; clicking it opens a panel with provider status and a GitHub workflow title.
  • Color and sound together. Claude, ChatGPT, Grok and Gemini have distinct colors and tones. CI results distinguish passed, failed and cancelled runs.
  • Fit the actual tools. Desktop accessibility controls supply response-state observations; a Chrome extension handles Grok and Gemini; the GitHub CLI supplies authenticated workflow metadata.
  • Keep the data footprint small. The AI observers pass state rather than prompts or answers. The browser bridge stays on the local machine and requires a generated connection token.

What changed through use

The first chime was too quiet. It became a sustained alert repeated twice, with frequencies that were easier to hear on laptop speakers. An early desktop detector also missed ChatGPT’s idle composer; inspecting the installed app identified the control it actually exposed.

Feedback then drove the floating-icon mode, persistent unread colors and a smoother panel transition. Account-wide GitHub monitoring followed, adding repository and workflow titles, silent startup snapshots and one alert per completed run attempt.

What is working

A working Windows companion for personal use.

The user confirmed the stronger chime was audible. The build passed 23 automated checks covering detection, local delivery, CI run tracking and widget behavior. Read-only GitHub access was verified across nine owned repositories at the time of implementation.

Implementation: Python standard library and Tkinter, a small C# accessibility probe, a Chrome extension, and GitHub CLI integration. The source and setup guide are maintained in a private GitHub repository.

Limits and next steps

Desktop and browser response detection is experimental: a response ending does not prove a task succeeded. App layout changes, minimized windows and suspended tabs can hide signals. GitHub alerts use workflow conclusions and polling, so they are delayed rather than instant; they do not represent an entire pull request’s combined checks.

Next priorities are broader live compatibility checks, clearer connection diagnostics, and simpler first-run setup. No adoption or time-saved claims are made from this personal-use build.
