Vantoryn: from project evidence to governed decisions

A project intelligence workspace designed to explain what changed, who owns the next step, and what evidence supports a decision.

The problem

A project can have plenty of updates and still lack a clear explanation of its current position. Evidence, work, decisions and meeting records often live apart. A status summary is useful only if someone can trace its claims, identify the responsible person and understand what is still unknown.

Vantoryn explores a workspace where project context supports decisions directly, instead of adding another disconnected dashboard or a generic chat interface.

The experience

The prototype connects Briefing, Review, Work, Attention, Decisions, Meetings, Reports and Activity. List-and-detail views keep the relevant record and its supporting evidence together. Search, filters, record editing and exports make the workspace usable beyond a static mockup.

  • Evidence before certainty. Surface missing information and risks alongside the records that support an assessment.
  • Decisions as living records. Preserve rationale and revisit decisions when circumstances change, rather than erasing their history.
  • Project-native assistance. Use a persistent intelligence entry point to explore changes, ownership and next steps across the workspace.

Architecture decisions

The project is evolving from browser-local prototype state toward PostgreSQL-backed project events and current-state records. Work and Decision mutations use authorized transactions to update versioned records and append their associated events together.

A governed tool registry declares roles, action effects and approval requirements. The model adapter helps interpret language; executable actions are constructed locally and checked against the product's rules. Consequential write tools require explicit approval.

The provider-neutral adapter supports local Ollama inference and a deterministic fallback for connection, timeout or invalid-response failures. This keeps model availability separate from the core action and policy boundary.

Current implementation

A working development prototype with an evolving intelligence backend.

The repository includes the multi-screen React workspace, PostgreSQL event persistence, project intelligence services, a governed action registry and model-adapter implementations. Automated test suites cover these areas; their presence is not a claim of production acceptance.

The product work connects interface design with data modeling and authority boundaries: a recommendation should explain its evidence, and an action should have an accountable execution path.

What remains

Project-memory retrieval, relationship modeling and broader end-to-end validation remain development priorities. The workspace is not presented as a production-ready multi-user service, and no adoption, accuracy or time-saved metrics are claimed.

Vantoryn is a working project name. The central lesson is durable: useful project intelligence needs traceable context and controlled actions as much as fluent language.
